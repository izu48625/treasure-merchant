# 時空の財宝商会 R5.9 — 装備・ジョブのマスターデータ設計案

作成: 2026-10-28 / Status: design draft (仕様提案・未実装)

## 0. 目的・非対象
- 既存の財宝20点、ガチャ、相場、図鑑、7枠装備、探索、IndexedDBセーブを壊さず、装備280点（武器160、頭28、胴28、脚24、アクセサリー24、探索道具16）から将来1,000点以上へ拡張できる構造を策定。
- ジョブ20職＋初期の「一般人」を永久解放式で追加可能にする。ジョブは出撃前に1職選ぶ。死亡時の装備ロストは従来どおりで、ジョブ解放は失わない。
- 本ファイルは設計書のみ。抽選率、公開ガチャ内容、旧アイテム性能、保存形式、ゲーム本体コードは未変更。
- 将来の戦闘AI・地形・ボス・回復アイテム・画像の実装は別工程。未実装のジョブ効果はデータだけ予約し、効いたふりをしない。

## 1. 現行実装の確認事項
- `exploration.js` の基本値: プレイヤー HP100 / 移動118px/s / 重量12kg（リュック+6kg）/ 探索240秒。
- 武器タイプと補正: strike（射程64, 間隔.77秒, 命中倍率1.35, 最大2体）, rapid（49, .30, .72, 1体）, reach（104, .72, 1.00, 1体）, unarmed（43, .62, .85, 1体）。
- 敵 HP normal=35 / fast=23 / heavy=94、攻撃 normal=9 / fast=7 / heavy=20。
- 現行防御は被ダメージから最大12を減算する固定値。後述する防御の割合式は新仕様であり未実装。
- 旧アイテムは `ITEMS[].id` (`ITM-00001`形式)、静的レア度、`state.inv[].uid/id/q` により管理。品質 q=0..3。
- 前回の「攻撃力/攻撃間隔」だけのDPS表は現行 `style.power` を反映していない。最終ダメージ/DPSを評価するときは攻撃タイプ倍率も使用。

## 2. データの責務を分離
1. **ItemCatalog**: `id`, `name`, `rarity`, `group`, `category`, `base`, `image`。既存財宝と新規材料・新規装備の基礎カタログ。既存 `ITM-*` IDは改変しない。
2. **EquipmentMaster**: `equipmentId` -> `itemId`, `slot`, `family`, `weaponStyle`, 攻撃/防御・重量、効果定義、装備・入手条件。アイテム本体と分離した静的定義。
3. **EquipmentInstance**: 所持実物（既存 `uid`, `id`, `q` に、任意の `enhanceLv`, `branchId`, `rolls` を段階追加）。同じ武器名でも別UIDを維持。
4. **JobMaster**: `jobId`, `name`, `role`, `effects[]`, `rarity`（入手希少性、強さではない）, `portrait`, `requiredFeature`。
5. **PlayerJobState**: `unlockedJobIds`, `selectedJobId`, `jobMedals`。出撃時のジョブ1職をスナップショット化。ジョブの解放・メダルは装備ロスト対象ではない。

装備7枠は weapon / weapon2 / head / body / legs / accessory / tool のまま。ジョブは装備枠を消費しない。
武器のメインとサブに同一UIDを装備できない既存制限を維持する。

## 3. 提案する共通ステータス
| 項目 | 初期 | 最終上限（仮） | 備考 |
| --- | ---: | ---: | --- |
| HP | 100 | 250 | ジョブ・防具・アクセサリー後に制限 |
| DEF | 0 | 20 | 新計算式へ移行した出撃のみ |
| 物理軽減率 | 0% | 50% | DEF/(DEF+20) |
| 移動速度 | 118px/s | 190px/s | 重量超過倍率の**前**に制限 |
| 運搬上限 | 12kg | 30kg | バッグ内の戦利品重量のみ。装備重量は未算入 |
| 属性軽減率 | 0% | 60% | 物理と重ね掛けしない属性別判定 |
| 武器基礎攻撃値 | 個別 | 100 | 武器定義+派生の基準 |
| 武器表示攻撃値 | 個別 | 150 | 品質・強化・ジョブ補正後の上限 |
| 攻撃間隔 | 個別 | 最短.25秒 | 武器とスキルで変化 |
| 近接射程 | 個別 | 最大150px | 遠距離は上限300px |
| 同時攻撃体数 | 1体中心 | 最大4体 | 集団火力の検証必須 |

将来の防御計算: `rate = min(.50, DEF / (DEF + 20))`、`physicalDamage = max(1, round(rawPhysical * (1-rate)))`。属性攻撃はその属性への耐性で別計算し60%以内。複合攻撃は物理/属性成分に分割し、同じ成分へ物理軽減と属性軽減を二重適用しない。

速度: `rawSpeed = min(190,(118 + gearSpeedFlat) * (1 + jobSpeedPct))`、`actualSpeed = rawSpeed * weightFactor`。weightFactorは既存の 1.0 / 0.4 / 0.2 を維持。実際の重量上限は `min(30, 12 + toolCapacityKg + jobCapacityKg)`。

## 4. 武器ごとの実効DPSと性能基準
- 各武器は `baseAttack`, `intervalSec`, `rangePx`, `arcRad`, `maxTargets`, `weaponStyle`, `effectIds` を保持。
- 品質補正 q=0..3: 0.95 / 1.00 / 1.07 / 1.15。強化段階0..5: `1+0.06*level`。レア度は別軸（入手希少性、固有特性、見た目）。既存市場の価格用 `QM` を戦闘倍率へ流用しない。
- `shownAttack = min(150, round(baseAttack * qualityMult * enhanceMult * (1 + jobWeaponPct) + flatAttackBonus))`。
- `hitDamage = max(1, round(shownAttack * stylePower * enemyAffinity))`。属性・状態異常は別イベント。
- `singleTargetDPS = hitDamage / adjustedInterval`。最短間隔は0.25秒。上限は単なる攻撃速度/表示攻撃力の個別上限では守れないため、装備マスターを作成する際にDPS監査する。
- 原則の実効単体DPS帯（出撃時・敵相性なし）: 序盤18〜45 / 中盤45〜95 / 終盤90〜220。これはマスター監査の警戒値で、実時間の戦闘結果を保証しない。
- 敵撃破目安: 通常1.5〜3秒 / 重装4〜8秒（同格装備）。実際の撃破時間は初撃がすぐ出るため、`(ceil(HP/hitDamage)-1)*interval` に接敵・敵挙動時間を足して判断する。

## 5. ジョブ20職＋初期一般人
- `JOB_CIVILIAN`（一般人）を最初から恒久解放。追加20職は入手後恒久解放、出撃前に1職選択。死亡・時間切れ・装備ロスト後も残る。
- ジョブのデータは `effects: [{key, value, targetTag?, availability}]` として、武器マスターのタグを参照して発動する。未実装の効果は `availability: planned`。
- ジョブのレア度は能力の上下を直接決めず、抽選希少性・固有性を示す。ガチャ確率はジョブ種類・メダル経済を決めた後に別途試算。

## 7. 保存、途中復帰、ガチャの安全対策
- ユーザー所持アイテムの `uid`、旧アイテム `id`、品質 `q`、ロック状態はそのまま。追加 `enhanceLv` / `branchId` は欠落時0/nullで互換。
- `initial()` には将来 `unlockedJobIds:["JOB_CIVILIAN"]`, `selectedJobId:"JOB_CIVILIAN"`, `jobMedals:0` を追加。旧セーブには欠落時デフォルトを補う。未知のjobIdは一般人へ安全にフォールバック。
- 出撃時に `jobId`、`combatRulesVersion`、最終HP/DEF/速度/武器プロフィールを既存の `exploreRun` スナップショットへ記録。探索中の職業変更は禁止。復帰時は確定済み報酬/敵/HPを再抽選・再計算しない。
- 既存の `exploreRun.v=1` と保存済みの戦闘計算をむやみに変更しない。新出撃のみ `combatRulesVersion:2` を使用。旧チェックポイントは現行の固定値防御方式を維持し、正常帰還または喪失まで安全に終えられるようにする。
- もしジョブガチャを導入するなら**既存財宝ガチャと抽選・通貨・天井を共有しない**。別のジョブ券・抽選記録を設計する。重複ジョブはメダルへ一度だけ変換し、JobMasterを重複追加しない。
- ジョブガチャは開始時に結果・消費・重複変換先を封印し、IndexedDBコミット後に結果表示。再起動時も同じ結果。課金・広告は今段階で導入しない。

## 8. 品質・バランスの自動監査条件
- 280装備のID、参照itemId、slot、タグ、0以上の重量、武器系統、同時対象数、効果keyの妥当性。将来1,000件でも一定の検証。
- 21ジョブ（20職＋一般人）のjobId重複ゼロ、定義外の効果keyゼロ、使用できない効果は `planned`。
- HP<=250、DEF<=20、重量補正前の速度<=190、バッグ容量<=30、表示武器攻撃<=150、攻撃間隔>=0.25、射程・攻撃対象数の上限。
- 武器タイプ係数を含めた単体DPSと3〜4体同時の総DPSの偏り検知。序盤18〜45、中盤45〜95、終盤90〜220は「バランス監査の目安」であり、違反アイテムはレビューしてから採用。
- 現行敵HP23/35/94でのサンプルTTKと、将来の敵HP・被弾・重量状況での戦闘実測。実機Safariによるタッチ、長時間fps、IndexedDB容量不足、連打、タスクキル、旧途中セーブも必須。
- 旧20アイテム・市場/ガチャ・保存と装備ロスト二重精算を壊さない回帰テスト。
