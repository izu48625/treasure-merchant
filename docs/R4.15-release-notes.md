# R4.15 — スロットを含む全抽選のタスクキル結果固定

更新日：2026-10-24

## 背景
R4.14では、ルーレットの賞品（財宝ID・品質）とガチャの結果をセーブし、IndexedDBのコミットを待って演出・結果画面を開始する仕組みを導入した。一方、スロットだけはSTOPを押した時点で未停止リールを新しく抽選していたため、途中でタスクキルした場合に「その回の最終結果」が未確定だった。

## R4.15で実装したこと
- **スロットの開始時点で3リールすべての絵柄を独立抽選して確定する**。スロット当選種類は従来どおり5絵柄・全組合せを使用し、確率と払い戻し倍率は変更しない。
- 財宝当選の組合せなら、開始時に具体的な財宝ID・品質も抽選して `state.arcadeSlotPending.reward` に保存する。対象財宝が存在せず現金代替になる場合も開始時に固定する。
- 新しい `slotVersion:3` では、`sealedRolls` が結果3個の確定データ、`rolls` は停止操作で公開した分だけ値が入り、残りは `null`。ユーザーに見せる画面は従来と同じ「手動停止／残り一括停止」。
- **タスクキル・ブラウザ再起動・スロット中断・一部のリールだけ停止した状態からの再開でも、その回の絵柄と財宝は変わらない**。タスクキルによる再抽選はできない。
- 一括停止を3回の独立保存から**1回の永続化トランザクション**に変更。IndexedDBでも1クリックで残りをすべて公開・精算し、保存中の連打で二重付与しない。
- 遊技場の説明文と開始時の確認メッセージを、STOP時抽選ではなく「開始時に結果を確定してSTOPで公開」に修正。
- **旧スロット途中記録（slotVersion未設定 / v2）を保護**。すでに停止した絵柄はそのまま保存し、未停止リールと財宝報酬は既存セーブの安定した値を使って決定的に補完・封印するため、旧途中記録でも再起動ごとに結果が変化しない。
- 旧セーブの基本バージョン番号と保存キーは維持。ルーレット・ガチャのR4.14保存方式も維持。

## 検証
- localStorage模擬再起動テスト **24チェック PASS**：3つ揃いの財宝賞品について開始時の確定値、賭け金、停止済み・未停止の絵柄、再起動、受け取り、二重STOP拒否、過去結果再表示、異常セーブ拒否を確認。旧v2セーブの決定的移行も検証。
- IndexedDBのトランザクションを意図的に遅延させたテスト **14チェック PASS**：スロット開始時の保存待ち・2度押し防止・一括停止1トランザクション・決着後の保存、ガチャ10連の二重引き防止・結果保存を確認。
- R4.14のルーレット賞品ID・品質の事前確定、旧途中記録の安定報酬、ガチャ1/10/50連の履歴保存、保存コミット待ちの仕組みはそのまま。
- JavaScript構文検証PASS。以上は**模擬ブラウザの機能検証**であり、iPhone SafariのOSタスクキル実機テストや実際のIndexedDBトランザクションの耐久性、容量不足／多タブ競合を検証したものではない。

## 重要な限界
- スピン開始の保存処理が**完全にコミットされる前**にOSがアプリを強制終了させた場合、その回の操作そのものがなかった状態に戻り得る。保存完了するまでは画面演出を開始せず、通常操作では結果を見てからロールバックする状況を避ける。
- 端末内に未来値を保存する方式なので、端末のセーブ・プログラムを解析／改変する技術的なユーザーから完全に結果を隠すものではない。オンラインランキングや不正対策にはサーバー権限が必要。
- フリーズ、プライベートブラウズ、ブラウザのデータ消去、空き容量不足による保存失敗などのケースではバックアップを推奨。
