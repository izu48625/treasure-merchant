# R5.2.3h — 4種類の宝箱画像を再切り抜きして搭載

## 背景
R5.2.3gで表示中にアルファを修正する方法を追加したが、形の欠けや背景の残りは元画像の切り抜きが原因。4種類の元PNG（いずれも1254×1254 RGBA）が作業環境に残っていたため、それをもとに新しい素材を作成。

## 実装
- 元PNGに存在する非常に薄い孤立透明画素（alpha < 9）を除去し、実際に宝箱が存在する領域をクロップ。
- すべて680×530の透明キャンバスに統一、最大625×475で縮小し、周辺余白を確保。
- WebP quality 84。実際のWebPサイズは通常98,076B／歴史151,436B／現代114,154B／高級111,066B。
- GitHub Git Blob、Git Tree／Commitの形で、現在のmainに4つの`assets/gacha/frames/chest_..._closed.webp`を直接置換。
- `gachaChestPath`が `?v=R5.2.3h` を付けて読み込むよう更新し、Safariの旧キャッシュを回避。
- CSSは表示中のズームを1.0倍にする。透明余白を維持したまま`object-fit:contain`で表示。
- `chest-cutout.js`をHTMLから外し、新素材の輪郭をブラウザー側で再編集しない。

## 保持
- 旧画像はGit履歴に存在するため戻せる。
- 他の8フレーム（opening/open）は未変更。
- 抽選結果、天井、保存、ガチャボタン・所持品・図鑑は未変更。

## 検証
- GitHubツリー上の4ファイルのBlob SHAとファイルサイズが作成したWebPと一致。
- `gacha-ui.js`と`index.html`のJS構文が通過。
- R5.2.3h URLと閉じた画像のcache-bust参照を確認。
- 最新版iPhone Safariの実画像表示、閉じた状態→開封中の演出切替の手動確認は未実施。
