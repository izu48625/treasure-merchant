# R5.16 — iPhone移動中の同時タップ不応答を修正

## 不具合の再現条件
プレイヤーが左下の仮想スティックに指を置いたまま移動中、別の指で右下の「攻撃」や「調べる」をタップしても動作しない。停止してからの通常タップでは動作することがある。

## 原因と修正
R5.15は透明ジョイスティックの重なり順とボタンの無効化条件を修正したが、**第二指がボタンに触れた際のイベント発火経路を変えていなかった**。iOS Safariではマルチタッチ中の第2指で通常の `click` が合成されない場合があるため、本文の `document.body` の `click` デリゲーションだけに依存する設計は不適切。

- `exploration.js`: `bindMultiTouchActions()` を追加し、探索画面の `.exp-action-grid` にネイティブ `touchstart`（`passive:false`）を登録。第2指のタッチ開始で即時 `window.explorationAction(button)` を呼び出す。
- 左指ジョイスティックのPointer IDとキャプチャ処理は維持し、右指のタッチでは移動状態を触らない。回収画面を開いた時だけ従来のゲーム完全停止が発生する。
- 対象ボタンの `touchstart` で `preventDefault()`。WebKitがそれでも `click` を合成した時には二重発火しないよう、同じボタン・直近650msのクリックのみ捕捉して停止。
- マウスクリック、キーボード由来のクリック、スクリーンリーダーによる通常のボタン操作は従来のクリックデリゲーションを引き続き使用。
- `exploration.css`: アクションボタンの `touch-action:none` を指定して二本指パン／ズームへの誤解釈を抑える。R5.15で修正したボタンと透明ジョイスティックの重なり順を維持。
- `index.html`: R5.16のJS/CSSを読み込ませてiPhone Safariの以前のキャッシュを回避。
- 攻撃射程・クールダウン・被ダメージ・ドロップ・脱出場所・地図アイテム・ガチャの結果・セーブ形式に変更なし。

## テスト
- 新しい `tests/exploration-multitouch.test.cjs` に6項目。左指で仮想ジョイスティックを押さえたまま、右指が「攻撃」「調べる」に触れるイベントを独立に模擬。
- 操作時に左指の `run.joy` が継続すること、棚を開くと時間停止になること、連続攻撃とクールダウン、Safari合成クリックの二重発火防止、マウス入力維持、CSS操作優先度を確認。
- 旧5スイート42項目と合計で**V8模擬実行48/48成功**。
- **iPhone Safari実機でのマルチタッチ試験は未実施**。ブラウザー実機固有のタッチキャンセルやブラウザー戻るジェスチャー等を完全に検証したものではない。

## 実機検証手順
1. https://izu48625.github.io/treasure-merchant/?v=R5.16 を開く。画面のバージョン表記がR5.16か確認。
2. 廃商業区へ出撃して左指を画面左下に置き、スティックを傾けたまま離さない。
3. 右指で「攻撃」を押す。プレイヤーが移動を継続したまま攻撃演出と「攻撃！」が出るか確認。
4. 同じく左指を押し続け、棚・ロッカーの近くで右指で「調べる」。回収リストが開いてゲームが完全停止するか確認。
5. スティックを離した後も、攻撃／調べる、地図、一時停止、バッグが通常どおり動くか確認。

同時操作に失敗した場合は、端末画面の録画から手指の位置とボタンの状態を見て、touchstartが届かないのか、到達後に操作が拒否されているかを切り分ける。
