# R4.12 — ガチャ・スロット・ルーレットの周回UI改善

更新日：2026-10-24

## 方針
既存のゲームルール、ガチャ・スロット・ルーレットの排出率、ゲーム内Gの賭け条件、個別の抽選方法を変更せず、連続プレイ時の画面スクロールとタップ数を減らす。
自動周回・賭け金の自動消費は実装しない。各回はユーザーの明示操作で開始する。

## 追加・変更内容

### ガチャ
- 各ガチャの結果モーダルに **「同じN連をもう一度」** を追加（1／10／50連、通常・歴史・現代・高級10連）。結果を最後まで表示／一括表示したときのみ表示し、誤って途中で再抽選しないようにする。
- 連続時も種類・回数・テスト/通常モードを維持。ただし初回無料10連は一度きりのため、初回分を繰り返す場合は通常のガチャへ移行し、正式版での支払い・権利条件をチェックする。
- ガチャ画面上部に **「結果を即表示」** のON/OFFを追加。OFFは従来どおり宝箱を開けて1品ずつ確認でき、ONは抽選後すぐ結果一覧へ進む。
- 即表示の状態はこのタブのセッション内だけ保持。所持品やセーブには変更を加えない。
- 新しいガチャ抽選が行われるのは必ず「もう一度」を押したタイミング。1クリックで複数回の自動抽選を開始しない。

### スロット
- 従来の各リールの **個別「停止」** は維持し、途中で **「残りのリールをまとめて停止」** を追加。
- 一括停止も独立した既存の `arcadeStopReel` 抽選を残りリールの分だけ実行。押すまで結果を決定せず、目押しの確率操作はない。
- 停止後の主要ボタンは **「同じ賭け金で次のゲーム」** と表示。賭け金は従来の選択状態を保持する。
- 確率表・長い説明は開閉可能な詳細情報に移動して、停止ボタンと次の開始ボタンをリール付近に配置。
- 二重STOP、一括STOPの再押下、再起動後の途中リール復元をテスト。

### ルーレット
- 通常の演出は従来どおり約8.5秒・22回転以上。
- 回転中だけ **「結果へ（演出を省略）」** を表示。押した場合は現在確定している当選枠からその場で精算し、抽選結果は変更しない。
- アニメーションの古い終了コールバックを無効にする `arcadeSpinToken` を追加。スキップ後に次の回転を開始しても、前のタイマーが後の回転の精算を割り込まないようにした。
- 結果確定後のボタンは **「同じ賭け金でもう一度」** に変更。以前の当選枠・高騰などの抽選処理や賭け金の確認ダイアログは維持。
- 賭け金選択・開始／結果確認ボタンをルーレットのすぐ下へ配置。確率表は開閉可能な詳細情報として下に移動。
- ブラウザを途中で閉じた場合は、保存済みの `arcadeRoulettePending` を従来どおり引き継ぎ、「結果を確認する」から一度だけ精算できる。

### UI
- CSSクラス `gacha-loop-tools`, `gacha-loop-footer`, `arcade-loop-panel`, `arcade-loop-main`, `arcade-loop-disclosure` などを追加。
- 主要ボタンは大きめのタップ領域を維持。確率／ルールは `details` と `summary` で展開可能。
- `arcade.js`, `arcade.css` のクエリバージョンを更新し、古いキャッシュを避ける。

## 回帰・耐久検証
- モックDOMと同じスクリプトで **41項目**：ガチャ通常10連・複数連続10連・1回引き・高級10連・現代50連と繰り返し、結果一覧のON/OFF、累計ガチャと所持品が一致。
- ルーレット：当選枠をコントロールして2倍Gが1回だけ付与されることを検証。演出スキップ後に別のルーレットを始め、**前のタイマーが後の結果を変えない**ことを確認。通常8800msタイマーも維持。
- スロット：開始時点では3絵柄は未抽選、手動で1停止、一括停止で残り2リールを抽選して一度だけ精算。再スタート後も未停止の3絵柄はnull。一括停止の二度押しで余分な報酬は付与されない。
- 再起動を挟む **18項目**：ルーレット中断→精算→再起動、スロット1リール停止→再起動→残り一括停止→再起動、Gと途中データが維持されることを確認。
- 41+18=**計59項目** のJavaScript模擬試験でPASS。

## 限界と次の課題
- **iPhone Safari実機・GitHub Pages配信反映の確認はまだ未実施**。モバイルでのレイアウト、片手操作、回転終了時のアニメーション、ブラウザバックグラウンド復帰を要確認。
- IndexedDBでの多タブ競合、ストレージ容量不足、賭け金や財宝の極端な件数に対する負荷試験は別途必要。
- 旧セーブ形式を維持したままのUI変更であり、対人ランキングや課金・広告は未接続。
