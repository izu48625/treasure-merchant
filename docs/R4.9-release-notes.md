# R4.9 — システム＆UI改善の第1段階

更新日：2026-10-24

## 方針
R4.8までに成立した**基本的なプレイ要素は原則固定**。以降は遊びの追加より、データ安全性・描画速度・モバイル操作・公開品質を優先する。

## 実装済み（R4.9）

### 1. ホーム「6時間後の注目ジャンル」のバグ修正
- ホームの市場ニュースは古い `event(hour()+6)` を参照していた。R4.6以降の高騰イベントは未来の詳細を返さなくなったため、6時間後のグループが正しく出ない可能性があった。
- `forecast(6)` の確定済みジャンル予報を参照し、絶対変動率の大きいジャンルを表示。
- 上昇/下落/横ばいを予報区分7段階で表し、割合を併記。以前の「予報は確約ではない」という説明は、**ジャンル指数について実際に確定している**現在仕様と矛盾するため変更。
- 個別財宝・高騰イベントによる実売却額までは保証されない点は市場画面に残す。

### 2. 大量の所持品に対する資産計算の高速化
- `ownedValue()` はすべての所持品で `price()` を呼んでいたが、**同じ財宝ID・品質・複製フラグの組**をまとめ、価格はグループごとに1回計算し `数量 × 単価` で集計するよう修正。
- ホームの価値上位3件を求める際、全所持品の配列コピーと全件ソートを廃止。上位3件を走査するだけの処理へ変更。価値が同点の品は以前と同じく元の順序を維持する。
- 50,000点のモックデータ検証：従来型の逐次価格合計203ms／新方式15ms、トップ3抽出17ms（実行環境内の参考値）。結果は元とBigInt単位で完全一致。
- これにより、ホーム・所持品・資産画面などで繰り返し使われる時価計算の負担が軽くなる。

### 3. 市場チャートの時点確認
- 「48時間」「7日間」の既存チャートの下に、**横方向のスライダーと選択時刻・ジャンル指数の数値表示**を追加。
- 全市場モードでは5ジャンル、単一ジャンル表示ではそのジャンルの指数を表示。
- ブラウザの `input` イベントでは数値欄のみを差し替え、チャートやページ全体を再描画しない。iPhoneのスクロール・日本語入力の既存挙動に影響しにくい設計。
- 期間変更時はカーソルを現在時刻へ戻す。変更は表示に限り、売却価格・相場確定・当選確率には影響しない。

## 回帰検証
- HTMLのインラインJavaScriptと外部 `arcade.js`・`rich-ranking.js` を連結して構文検証。
- セーブ読み込み、市場履歴V4の形式、6時間後の確定予報とホーム表示、グラフ48時間・7日間、5ジャンル・単一ジャンル、スライダーの入力処理、価格とランキングの等価性など**19項目**。
- 50,000点の所持品を用いて、従来の全件逐次価格合計と集計値が完全一致すること、および従来の全件安定ソートと上位3件のID順が一致することを確認。
- ブラウザの実機・IndexedDBの多タブ競合・iOS Safariスクロール位置・大容量保存の挙動は未確認。
