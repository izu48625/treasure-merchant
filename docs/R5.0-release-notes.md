# R5.0 — スロット筐体をゲームとして再設計

更新日：2026-10-24

## 実装したもの
- 絵文字主体の小さな3リール表示を廃止。専用SVG5点（古金貨／引換券／財宝箱／宝石／王冠）を `assets/slot/` に新設。
- `slot-ui.js` でゲームルールとは独立した画面を実装。`slot-ui.css` に大型3リール、立体筐体、金属銘板、独立STOP、払戻の演出をまとめた。
- ベットを明示したSPINを一押しで開始（毎回のOS確認ダイアログを削除）。賭け金100/1千/1万/10万/100万G、3つのSTOP、残り全部STOP、同じ賭け金で再実行は維持。
- サウンド初期OFF。オプトインでWeb Audioの短い停止／始動／当選音を再生。高速表示のON/OFFを追加。設定は独立したlocalStorageキー `treasure-slot-ui-v1` を使用し、ゲームデータには関与しない。
- 3つの財宝箱が揃った場合、開始時に封印済みの財宝ID・品質を払戻結果にも任意メタデータ `slotPrize` として保存し、実際のカタログ画像・名前・レア・品質を結果画面で表示。
- 旧セーブとの互換性のため `slotPrize` は任意とし、JSONインポートでは存在する場合にID/品質/3つの財宝箱の整合性を検証する。
- CSSアニメーションと表示処理以外で再抽選を行わない。途中セーブと抽選のロジックは `arcade.js` のまま。
- 汎用ダッシュボードへの逆戻りを防ぐデザイン規則を `DESIGN.md` に保存。

## 状態保存の順序
1. SPIN：既存の `arcadeSlot` が `sealedRolls` と `reward`、賭け金を保存してからリールを表示。
2. STOP：既存の `arcadeStopReels` が各リール公開を保存した後、停止フィードバックを表示。
3. 完了：既存の `arcadeFinish` が払戻確定を保存してから新しい獲得演出を出す。
4. 再起動：未停止のリールは回転表示に戻るが、停止済みのリールと封印された結果は不変。
5. 結果画面の飾り・音・高速設定は当選確率に影響しない。

## 今回の確認結果
- JavaScript構文検査（arcade.js／slot-ui.js／index.htmlのインラインJS）を実施。
- `arcadeSlotOutcome` の5×5×5＝125通りを確認。ハズレ60、2つ一致60、各種3つ揃い1×5。
- モック実行で以下7条件を確認：初期賭け金減算、途中STOPの保存、再起動時の結果不変、4倍Gの払い戻し、二重精算防止、財宝ID・品質保持、財宝の1回付与。
- R4.17比でルーレット抽選関数、スロットの当選判定、途中セーブ検証関数が同一であることを差分監査済み。
- 現在は実機のスクリーンショット、iPhone Safariの画面寸法、クリック位置、OS強制終了の実機試験を**未実施**。完了済みと取り違えないこと。
- クライアントサイドでの不正操作耐性は対象外、将来オンライン要素を導入するならサーバー検証が必要。
