# R5.15 — スマホ探索の攻撃／調べるタップ不応答修正（2026-10-28）

## 報告
スマホでの探索操作中、攻撃ボタンと「開ける／調べる」ボタンを押しても反応しない。

## 原因分析
1. 透明な移動スティック操作領域 `#exp-stick-zone` が画面下部左50%を覆い、CSS重なり順 `z-index:11` で操作ボタンレイヤー `.exp-controls`（`z-index:10`）より上に位置していた。**左側が重なる端末幅・指の位置では、ボタンへのタップを透明ゾーンが受け取る**。
2. `#exp-interact` が探索対象から58px以上離れると `disabled` にされ、クリック自体が発火しなかった。対象の見た目は近くても当たり判定外で、案内が出ず故障のように見えた。
3. 攻撃は何も命中しない状況でも処理は動いていたが、アニメーション時間が短く、ボタン押下時に分かりやすいテキストフィードバックがなかった。

## 変更
- `exploration.css`: 移動スティック領域の重なり順を `6`、操作ボタン側を `12` にして逆転。バッグ `15`／停止メニュー `20` の優先順位は維持。
- `exploration.js`: 棚・箱の判定範囲を58px→78pxへ統一（新旧マップ双方）。脱出口判定58px・戦闘射程は変更なし。
- `#exp-interact` は無効化せず、対象の範囲外で押した場合も `interact()` に流して「近づいてください」と表示。
- 攻撃ボタンの実行結果を画面内に表示（`攻撃！`／`攻撃準備中…`）。攻撃クールダウン中は従来通り1回入力を予約し、攻撃/武器/敵HP等は変更しない。
- タップ説明用のメッセージは画面上に独立表示。操作を遮らないよう `pointer-events:none`、通常2.3秒で消灯。バッグの中にも従来の履歴を残す。
- `index.html` で `exploration.css?v=R5.15` と `exploration.js?v=R5.15` を指定してSafari旧キャッシュを回避。

## テスト
- `tests/exploration-controls.test.cjs` を新規追加（6項目）。ボタン経由の攻撃実行・連打待機・70pxからのコンテナオープン・対象がない場合の案内・CSS重なり順・アクションHTMLの存在を検査。
- 以前のマップ・回収・脱出テスト4スイート（36項目）と合わせ、**V8模擬実行42/42成功**。
- 未実施：**iPhone Safari実機のタップ試験**。実ブラウザーでの視覚・重なり評価も未実施。実機で特定の端だけ無反応なら画面幅/向き/表示倍率が必要。

## ユーザー確認手順
1. [R5.15版](https://izu48625.github.io/treasure-merchant/?v=R5.15) を開く。旧タブなら再読み込み。
2. 廃商業区で出撃。画面右下の「攻撃」を押し、`攻撃！` が表示されるか確認。
3. 棚・ロッカー・箱から約70pxに近づき「調べる」を押す。中身の選択画面で時間が完全に止まるか確認。
4. 対象がない位置で「調べる」を押した場合は、`棚やロッカーに近づいてください` が表示される。
5. 移動スティックを動かしながら攻撃・調べるボタンを片手／両手で押して、操作が奪われないか確認。
6. 一時停止・マップ・バッグ表示時に本来の背面ボタンが押せないことも確認。
