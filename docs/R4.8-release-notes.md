# R4.8 — 市場・遊技場の監査と品質修正

更新日：2026-10-24

## 修正した問題

### 1. 財宝の個別価格が上下しすぎる
- R4.7の `individualMult()` は時刻ごとに `910〜1090`（基準から±9%）を取り、安定ジャンルの指数（平均0.18%/h前後）を覆い隠していた。
- R4.8では直近2時間の保存済み乱数をブレンドし、ジャンルごとの個別補正を約±0.3〜0.8%に限定（現代±0.3%、歴史±0.5%、宝石±0.7%、骨董±0.4%、神話±0.8%）。
- **高騰イベントの1.45〜1.75倍は意図的に維持**。実際の財宝売価には市場指数、個別補正、イベント、品質、複製補正が掛かる。予報はジャンル指数だけであり、最終売却額までは保証しない。

### 2. 「横ばい」に偏る6時間後・12時間後予報
- 旧分類は1.4%未満をほぼ横ばいにしていたため、6時間予報の約66.6%が横ばいになっていた。
- 7段階に分類：**急騰（+2.5%以上）、上昇（+0.8%以上）、微上昇（+0.15%以上）、横ばい（±0.15%未満）、微下落（-0.15%以下）、下落（-0.8%以下）、急落（-2.5%以下）**。
- 予報は確定済みの6h・12h先の `marketV4` 指数から直接作成し、予報が当たる仕組みを変更しない。
- 1,500時間×5ジャンルのサンプル（6h予報7,500件）では、横ばいは658件（**8.77%**）。これはその1回のサンプルの測定で、固定の出現確率ではない。

### 3. ルーレットの報酬が回転開始時に付与される
- R4.7は抽選後すぐ払い戻し処理を行い、約8.5秒のアニメーション中も内部資産が増減していた。
- R4.8では**賭け金を開始時に1回引き、当選結果と停止角度だけ `arcadeRoulettePending` に保存**。賞金・財宝・ガチャ権利の付与は回転終了の8.8秒後。
- 停止まで結果テキスト・当選報酬を非表示にする。
- **リロード／ブラウザ中断時は、未決着結果をセーブから読み、明示的に「結果を確認する」ボタンから1回だけ払い戻し**。開始時に確定した抽選結果は変えず、再抽選もしない。
- アニメ中の再投入・ルーレット未決着のままのスロット開始を禁止。
- JSONインポート時に `arcadeRoulettePending` の指数・金額・角度を検証。
- 前のルーレットの結果がすでに支払い済みの旧セーブはそのまま読み込む（新フィールド欠如は `null`）。

### 4. 長期間放置した相場の履歴再生成
- R4.7では現在から過去672時間（28日間）以上の欠落があるとき、`marketV4` 全体を破棄して相場の歴史を新しく生成する仕組みだった。
- R4.8では既存の最終価格を引き継ぎ、24時間ずつの160基本パターン＋毎時乱数で相場を延長する。
- 履歴は最新256時間以内に保ちつつ、旧データを必要以上に初期化しない。
- 数年以上の異常な時計ジャンプを想定した上限処理では過去からの連続したサンプルを3年ぶん進め、イベント時刻も連動して調整する。極端な時計改変を完全に阻止する仕組みではない。
- 新市場の最終確定価格が既存行として残っている限り、再開時もそこを起点に将来を生成する。

## 変更ファイル
- `index.html`: 相場の個別補正、7段階予報、長期相場復帰とイベント日時の整合、新しいルーレット途中記録のセーブと検証、バージョン表記、JSキャッシュ更新。
- `arcade.js`: ルーレットの未決着記録・結果の確定後付与・ブラウザ再起動後の請求画面と二重払い防止。
- `README.md`, `docs/R4.8-release-notes.md`: 開発記録。

## 検証
- 市場・ルーレット合同回帰26項目：40日未起動、V4相場保存・再読み込み、ルーレット2倍Gを停止後に1回だけ付与、連打無効、JSON破損拒否を確認。
- 1,500時間×5ジャンルで個別価格の変動と確定予報の分布を再計測。最終売価の大きな変動は、高騰イベントにより意図的に起こり得る。
- 極端な5年時計ジャンプでは当初、イベントの時刻が相場と一緒に移動しないバグを発見・修正。修正後は48日・5年シナリオ10項目を通過。5年進行はテスト環境で約285ms。
- これらはJavaScript模擬実行での確認であり、**GitHub Pagesの最新配信・iPhone Safari実機・IndexedDB多タブでの競合・巨大インベントリ負荷は未確認**。本番互換性を保証するものではない。

## 残る課題
- iPhone Safariの実機で、市場の7段階予報、テキスト折返し、ルーレットの8.5秒終了・背景移動・再読み込みを確認。
- 保存競合（複数タブ）と容量不足ケースを実ブラウザで検証。テストでは localStorage フォールバックを利用した。
- グラフのタップ詳細表示、アイテム保有・売却タイミングの長期的ゲームバランス検証、サーバー共通市場・不正対策は今後の候補。
