# R5.2.1 — iPhone実機フィードバックに基づくガチャ画面仕上げ

作業日：2026-10-24

## 反映した変更
1. **4種類×3段階の宝箱の視覚サイズ正規化。** 元の透過WebP素材12枚は再圧縮せず保持。640×480の中で、通常・閉箱のアルファ外接幅約602pxに対し、他3種類の閉箱が433〜450pxという差を確認。表示に関して通常1.0倍、ほか約1.34倍で見た目の横幅と中心位置を揃える。開封途中は一律1.09倍、開封後は通常1.22倍・ほか約1.26倍の倍率を使用する（CSSのみ）。画像の中身・抽選に影響なし。
2. **開封と獲得品の演出を接続。** 保存確定した結果から対象財宝の画像を取得。閉じた箱→開きかけ→開き切る→財宝が箱からせり上がる→結果画面にフェードする流れ。開封のメインアニメーションは約1.1秒。表示ステップは保存済みの`gachaReveal`を参照し、演出側では乱数を使わない。
3. **獲得画像を拡大。** 単品の鑑定結果における画像表示領域を拡張し、個別財宝画像内部の余白をCSS拡大で補正する。10連・50連の画像も少し大きくする。レアリティ別の装飾は継続。
4. **スマホの表示密度。** 重複英語の削除、権利・残高・タブ・鑑定室の上下余白の圧縮。SR/SSR保証は折りたたまず配置を維持。
5. **下部の可視性。** 固定ナビの分だけ`.app`とガチャ画面のスクロール末尾に余白を確保し、Safariの安全領域にも配慮。表示領域の短い端末ではスクロールを許す。
6. **下部ナビの絵文字を独自5種類のSVG線画に置換。** ホーム・ガチャ・所持品・市場・遊技場の操作分岐はそのまま。
7. **開封モーション軽減対応。** `prefers-reduced-motion`の利用時はオーバーレイを即座に閉じて結果表示を妨げない。

## ファイル
- `gacha-ui.js`：封印の開閉コマと保存済み財宝の出現演出、簡素化ラベル
- `gacha-ui.css`：宝箱の見た目のサイズ調整、結果画像サイズ、縦方向のUI圧縮、下部ナビ余白／アイコン
- `index.html`：アイコン表示、R5.2.1読込と版表記
- `README.md`、`DESIGN.md`、本ファイル：ルールと検証内容の記録

## 既存機能の保護
`function gacha(type,count,mode)`（抽選・付与・課金テスト処理・保証）と`gachaRevealValid`（保存済み開封検証）を旧版と文字列比較し完全一致。開封ステップは従来どおり`saveWithCommit`の完了後に描画・演出開始。即表示・初回無料10連・高級10連・50連の処理を変更しない。
