# R5.2.3g — 宝箱の切り抜き境界の補正

2026-10-24

## 実機報告
R5.2.3fをiPhoneで表示したところ、通常／古代／現代／高級の宝箱に切り抜き残りや欠け、不自然な縁・影が見られた。CSSの倍率調整だけでは画像素材に焼き込まれた不完全な透明マスクは修復できない。

## 実装
- `chest-cutout.js` を新規追加。12種類（宝箱4種×closed/opening/open）のWebPのみ、ブラウザーが画像を読み込んだ時に透明度のエッジを補正。
- 8方向に連続する最大の宝箱領域を確認し、孤立した微小画素片を落とす。1pxの内部ピンホールは周辺8画素が確実に不透明な場合だけ埋める。
- 透明度のある縁のRGBを周辺の不透明領域に近づけ、黒／赤／青系の古い切り抜き境界にじみを軽減。
- 背景を一律に色指定で消すクロマキー処理は使わない。宝箱の暗い木材、金属、鍵穴などが消えるのを防ぐ。
- 既存の原画像は削除・変更せず、閲覧時にCanvasで補正した画像を表示。失敗したら元画像を使用し、抽選・セーブには影響しない。
- Safari向けに `image/webp` で出力し、同じ画像ファイルの重複変換を避ける簡易キャッシュを実装。元画像12種類すべてに対応する。
- `index.html` とガチャCSS/JSの読み込みバージョンをR5.2.3gに更新。

## 検証
- JS構文チェック通過。
- 模擬Canvas画像で孤立画素を除去、完全に囲まれた1pxの欠けを埋め、正常な宝箱画素を保全できることを確認。
- R5.2.3fの画像表示CSSと抽選・セーブの処理は維持。
- デプロイの成功確認。

## 制約
- この方法は**クライアントでの保守的な自動補正**であり、すでに数十px単位で欠けている宝箱そのものの描き直しや、複雑に背景が残った領域の手作業マスク修正と同一ではない。
- 変更後のSafari実機での見え方は未確認。まだ欠けが目立つ場合は元の12画像を個別にレタッチして差し替える必要がある。
- 補正に掛かる処理負荷が大きい場合はCanvas補正を無効化できるよう独立したJSファイルにしてある。
