# R4.14 — タスクキル・再起動時の抽選結果固定と保存監査

更新日：2026-10-24

## 監査の結論
R4.13では以下の例外がありました。
1. ルーレットは当選枠と賭け金は回転開始時に保存するが、**当選枠が財宝の場合は、財宝種類と品質が結果受取時に別抽選**されていた。再起動すると賞品が変わり得た。
2. ガチャで当選した所持品は保存されるが、`lastPull` と結果モーダルはメモリのみで、再起動すると「どの財宝を獲得したか」の一覧を再表示できなかった。
3. スロットは**各リールの停止操作の時点で抽選**する設計。停止済みのリールだけはセーブされるが、未停止リールは未抽選なので再起動後にも新しく抽選する。これは現在の仕様どおり。
4. R4.13のIndexedDBへの書き込みは非同期。結果表示がセーブ完了より先に進む場合、直後のタスクキルで結果が失われる可能性があった。

## R4.14の修正内容

### ルーレット
- 抽選開始時に当選枠に加え、財宝枠なら**具体的なアイテムIDと品質（0〜3）**も確定し、`arcadeRoulettePending.reward` に保存する。
- 当選した財宝は結果受取時に再抽選しない。ハズレ・G倍率・ガチャ権利は従来どおりの賞品内容。
- 保存済みのR4.8〜R4.13途中記録には `reward` がない。旧記録の財宝枠だけは、既存の**賭け金・ホイール角度・当選枠**から安定した賞品と品質を導く互換処理を追加。繰り返し再起動しても同じ賞品になる。
- ルーレットの回転タイマーは、開始記録（G減少・確定結果・回転状態）がセーブ確定した**あと**に開始する。
- 回転終了後の賞品・払い戻しと、`arcadeRoulettePending=null` は同じセーブ更新でコミットする。再起動しても二重付与を防ぐ。
- 最終結果テキストを `arcadeLastResult` に保存する。

### スロット
- 開始時にG減少と未停止の3リール `null` を保存。
- リールは停止時だけ独立抽選して保存。一括停止は3回の独立STOP処理を呼ぶ。**未停止リールが固定されるわけではない**。
- 途中の停止状態と、3リール確定後の結果・報酬・`pending=null` の書き込みが確定する前には次の表示へ進まない。
- 決着済みの直前結果は `arcadeLastResult` に保存し、起動後に再表示可能。

### ガチャ
- `lastGacha={type,count,items:[{id,q}]}` を最新抽選分だけセーブ（最大50件）。品質とIDは所持品に付与した値を使う。
- タスクキル後も「直近の獲得品」の一覧を再表示できる。互換保存（localStorage）とIndexedDBの双方を対象に初期化処理を統一。
- 抽選・獲得・最新履歴は同じセーブ更新で確定。セーブが終了するまで結果画面を表示しない。
- 保存待機中の二度押しを防ぐ。以前からの抽選確率、保証条件、料金・ガチャ権利のルールは変更しない。
- 復元JSONは最新ガチャ一覧や遊技場結果の形式を検証。古いセーブでは新フィールドを `null` に補完する。

### 非同期セーブ完了の待機
- `saveWithCommit()` と `awaitDurableRevision()` を追加し、セーブの改訂番号がIndexedDBトランザクションでコミットされたあとに結果画面・演出を開始。
- 完了前は操作の連打と予期せぬ全画面再描画を抑制。
- IndexedDBに書けないときのlocalStorage互換保存および保存失敗時の操作停止の既存設計は維持。
- **完全な耐タスクキル・不正防止を保証するわけではない**：OSによる突然の終了がトランザクションコミットの前なら、その回のクリック自体が保存されず、実行前の状態に戻り得る。結果をプレイヤーに表示するのはコミット後に限定し、この窓を減らす。端末内JSONの手動改変・多タブ競合・ブラウザのデータ削除は別課題。

## テスト
- 旧データ含むlocalStorageで、当選財宝IDと品質のタスクキル前後一致、ルーレット・スロット各精算の再起動、スロット一部停止の復元、ガチャ10連/50連結果一覧の復元、壊れた結果履歴のインポート拒否：合計38チェック（20+18、経過中の追加変更に合わせて再検証）。
- **保存処理を意図的に遅延**させたIndexedDB模擬テスト23チェック：開始時の賭け金と結果の書き込み確定まで回転タイマーを開始しないこと、ガチャが二度引かれないこと、スロットSTOPのコミットを待つことを確認。
- R4.8〜R4.13の旧ルーレット途中記録（財宝枠）の5回再起動・安定賞品付与：12チェック。
- これらは**JavaScriptの模擬DOM・差し替えた保存関数による検証**。実機のiOS Safari、実際のIndexedDBのOS強制終了／容量不足／ブラウザ背景タブ／複数タブ競合は未実施。

## 変更したファイル
- `index.html` — 最新ガチャ結果・直前遊技場結果の保存と復元、保存確定待機、旧セーブ移行、タスクキル対策。
- `arcade.js` — ルーレット賞品の事前確定、旧セーブの安定賞品化、停止処理の保存待ち、直前結果保存。
- `README.md` と `docs/R4.14-release-notes.md` — 監査記録。
