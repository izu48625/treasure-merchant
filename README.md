## 最新: R3.9（IndexedDB保存・旧セーブ自動移行）
- [R3.9をプレイ](https://izu48625.github.io/treasure-merchant/?v=R3.9-3cfe42b)
- **大容量セーブをIndexedDBへ移行**。これまでの `localStorage` キー `treasure-exchange-demo-r1` とセーブの `v:1` は保持する。初回起動時に旧セーブを読み、IndexedDBの **書き込みトランザクション完了後** に元のlocalStorage保存データを小さな参照マーカーへ切り替える。
- 起動前は操作不能の読み込み画面にし、非同期ロード中に初期データで保存・上書きされるのを防止。IndexedDB側に既存の保存データがある場合、原則そちらを読み込む。移行途中に旧localStorage側の更新版が残っていれば保存リビジョンを比較して新しいものを採用する。
- IndexedDBが使えない場合は**従来のlocalStorage方式にフォールバック**。保存エラーが起きた場合にもフォールバックを試み、両方失敗したらセーブ操作を停止して再試行・書き出しを案内する。
- **IndexedDB済みマーカーがあるのに本体データが読めない／消えている場合、空セーブで上書きしない。** 復旧案内を表示する。
- 設定（「試作版について」）に保存先表示と、フォールバック時の再移行ボタンを追加。既存の「セーブを書き出す」は継続。
- 確認した項目：旧セーブの移行・再起動読み込み、連続保存の順序、DB書き込み失敗→localStorage fallback→再試行、新規セーブ、参照マーカーだけ残りDBがない場合の上書き防止、**20,000点の所持品を使う模擬保存テスト**。JS構文検証。
- **注意：IndexedDBも端末内保存であり、クラウドセーブではありません。** Safariのサイトデータ消去・容量管理等で消失する可能性があります。大事なデータは「セーブを書き出す」でバックアップしてください。また20,000点テストはJavaScript模擬環境で、iPhone Safari実機のメモリ／性能／永続保存は未検証です。
- 今後の課題：iPhone Safari実機QA、セーブJSONの復元インポート機能、複数タブの競合対策、20,000点以上で毎回全所持品を複製保存しない増分方式、クラウドへのバックアップ等。
