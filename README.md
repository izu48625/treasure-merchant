## 最新: R4.3（商会遊技場：財宝大勝負・無料抽選・ルーレット・スロット）
- [R4.3をプレイ](https://izu48625.github.io/treasure-merchant/?v=R4.3-7391e1d)
- ホームから**🏦 商会遊技場**に進むと「財宝勝負」「無料チャレンジ」「ルーレット」「スロット」を切り替えられる。UI/処理は `arcade.js` と `arcade.css` に分離。
- **財宝大勝負**：複数種類・複数個の財宝を投入し、任意の目標財宝を狙う。成功率は投入した各財宝の基本金額合計÷目標基本金額×90%（上限90%）。複製品は基本金額の45%換算。相場や品質による補正なし。成功・失敗を問わず投入した財宝は消滅するが、**図鑑の発見履歴は永久に残る**。保護中・お気に入りは投入不可。
- **無料チャレンジ**：1日1回、Gやアイテム消費なしで選んだ財宝に挑戦。基本金額1,000G分を基準に成功率を計算（上限30%）。日付を `arcadeFreeDay` としてセーブ。
- **商会ルーレット／スロット**：ゲーム内Gの投入額を選び、G・ガチャ権利・財宝を抽選。双方とも当選確率と配当表を表示。投入Gは抽選前に消費。現状のガチャテスト版はガチャが無制限無料のため、獲得ガチャ権利が実際のガチャ回数を制約しない。
- **注意**：本機能は仮想G/仮想財宝のみ。現金化・換金不可、リアルマネー課金・広告・オンラインランキングとは未接続。抽選はクライアント上の試作ロジック。公開ランキング向けにはサーバー確定が必要。経済バランスは仮設定。
- 既存のセーブ `v:1`、IndexedDB v2、財宝20種、R4.2図鑑、R4.1リーグ、既存ガチャ率は継続。アプリ全体の模擬起動・10項目超の勝敗／現金／入手履歴／日次制限／復元検証を実施（iPhone Safari実機は未確認）。

## 最新: R4.0（JSON復元・所持品の増分保存・復元前バックアップ）
- [R4.0をプレイ](https://izu48625.github.io/treasure-merchant/?v=R4.0-a9ef8cb)
- **セーブJSONの復元機能を実装**。「試作版について」→「JSONから復元」から端末の `.json` セーブを指定可能。復元前に内容と所持品ID・品質・金額・累計記録・図鑑の整合性などを検証し、置換確認を行う。ゲーム内に存在しないアイテムのデータは、黙って削除せず復元を拒否する。
- **元のセーブを保護**。復元・全データ初期化前に現在のセーブをJSONファイルとして書き出す。IndexedDBでは同時に `backups/before-replacement` へバックアップを保存し、メタデータ・所持品の入替を同一トランザクションで行う。途中失敗時は既存の保存を維持。ブラウザ側でダウンロードがブロックされる場合があるので、必要に応じて事前に手動エクスポートすること。
- **IndexedDB v2：分割セーブ／増分書き込み**。`treasure-merchant-storage-v1` のDBをバージョン2に上げ、`state_meta`、`inventory`、`backups` ストアを追加。ガチャ・複製時の新しい所持品は追加、ロック変更はその1点だけ更新、売却は該当IDだけ削除。それ以外の資産・称号・市場記録等はメタデータのみ更新。**通常の保存で所持品全件を書き直さない**。
- R3.9以前の `saves/primary` 一括セーブおよびlocalStorage形式を初回起動時に分割ストアへ移行。旧DBストアは移行完了後も残し、旧セーブのlocalStorageキーと `v:1` を維持。分割セーブを読み込めない場合は、新規セーブによる上書きを防止する。
- **同じ端末の別タブで書き込みが競合した場合は安全停止**。保存世代番号の照合に失敗したタブから上書きせず、読み込み直しとメモリ内セーブの書き出しを案内する。
- 検証：旧R3.9セーブ／参照マーカーからの移行、50連で50件だけ追加、保護変更1件だけの更新、売却1件だけの削除、正しいJSONの復元・復元後再起動、不正JSONの拒否、DB容量エラー時のトランザクション全体ロールバック、複数タブ競合の上書き防止、**20,000点の模擬所持品保存**（変更1点だけ更新・連続のメタデータ保存で所持品の再書き込みなし）、JavaScript構文。
- 未実施：iPhone Safari実機でのJSONファイル選択・ダウンロード・保存挙動、長時間利用時の性能・ストレージ自動削除の耐性。IndexedDBは**端末内データでクラウドバックアップではない**。
