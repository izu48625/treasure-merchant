# R5.98 iPhone縦画面：探索中のHUDとマップ・ボタンの重なりを解消

## 実機報告（2026-11-03）
提供されたiPhone Safari実プレイスクリーンショット2枚では、R5.97の屋内施設V5で以下の状態：
- 下部の「攻撃／武器／調べる」「バッグ／AUTO」が施設床、壁、敵の警戒扇形や物資の上にかぶり、物資が隠れる
- 右中央の「詳細地図」が探索画面の上に浮いている
- SECURITY/CONTROLなどの大きなワールド内の部屋名がプレイヤー矢印や端末と重なりうる
- 上部のタイマー、体力、未発見、カードキー目的表示が視界の上側を占有している
- 既存のCanvas高さは最低360pxに固定され、狭い実表示領域でキャンバスが縮められると縦横比も一致しない可能性がある

## 方針：V5だけ操作と描画を分離、他のゲームルールは全不変
画面縦表示時に、上から以下の独立した領域を置く：
1. **上の情報レール**：戻る、タイマー、体力、敵、ポーズ／警戒・目的／区画名・詳細地図を並べる（安全領域を考慮）
2. **中央のプレイCanvasのみ**：プレイヤー、敵、警戒扇形、床、壁、物資だけを描く。以前の下部ボタン・地図ボタンを重ねない
3. **下の操作ドック**：左は透明の仮想スティック起動エリア、右は攻撃・武器・調べる・バッグ・AUTO。操作ボタンは44px以上を維持

V5以外（旧R3/R4地形）は従来の画面設計を維持する。アプリ商会・ガチャ・セーブ・戦闘抽選に触れない。

実装：
- `exploration.js`：V5だけ`exp-v5-layout`を付与。部屋名のDOMをCanvasの外側へ。Canvas高さはCSS実測に合わせる（旧360px下限をV5のみ160pxまで緩和）。
- `exploration.css`：一番後ろにV5専用上レール・中央Canvas・操作ドックの配置を追加。Safariの`env(safe-area-inset-*)`と`100dvh`を考慮し、幅375px以下や高さ610px以下に対応。
- `exploration-layout-v5.js`→`maps/indoor/tiled-runtime.js`：探索中の`drawAmbience`に`hideZoneBanners`フラグを渡し、PHARMACY/SECURITY/CONTROL/RECEIVING/STORAGE/ULTRA VAULTの巨大ワールド看板を隠す（マップの看板オブジェクトは削除しない）。部屋名は上の独立した区画表示で常に表示。照明、敵、カメラ、効果、警報は維持。
- `index.html`：R5.98のCSS・JavaScriptでキャッシュ更新。
- `tests/tiled-mobile-hud-r598.test.cjs`：V5専用CSSのレール・44pxタッチ面積、V5画面マークアップ、巨大ワールド室名の探索中のみ非表示（プレビューは表示）、旧モードとデータ互換性を検証。

## 未検証
- ユーザーのiPhone SafariでR5.98の操作性・縦横表示・画質・60fps・5分間周回は**未検証**。
- CSS DOM測定のコード検証とGitHub Actions CIの回帰は実機評価と異なる。
- 実機で重なりが残るかどうかは公開版R5.98で再確認が必要。iPhoneの拡大表示・ホームバー・Safari下部バー・文字サイズ設定で表示域が変わる可能性あり。
